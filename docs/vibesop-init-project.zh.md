# vibesop-init-project:项目治理

[English](vibesop-init-project.md) | 中文

`vibesop-init-project` 为仓库建立一套可长期运转的治理:文档怎么分区、哪些内容不公开、AI 指令文件写什么、这些决定记在哪里。流程原文是 [`skills/vibesop-init-project/SKILL.md`](../skills/vibesop-init-project/SKILL.md),本文面向使用者,说明它做什么、按什么方式做决定。

## 四个入口

第一次回复时,skill 根据探测到的仓库状态选择入口:

| 入口 | 条件 | 做什么 |
|---|---|---|
| 新项目 | 没有提交,或仓库里只有一个 README 和 LICENSE | 从零建立全部治理文件 |
| 存量项目 | 已有提交与代码或文档,没有治理记录 | 接入治理;存量文档原地登记,原有内容逐行保留 |
| 开源准备 | 仓库即将公开,或治理记录中的可见性改为开源 | 隔离私有内容、处理历史、补 LICENSE 与 README |
| 检查 | 治理已存在,用户要求验证 | 只读运行检查命令,不写任何文件;发现的问题以方案表形式给出 |

## 工作过程

每个入口遵循同一过程:探测(只读)→ 报告与选入口 → 决策提问 → 方案表 → 写入 → 验证 → 交付。

- 探测只读取信息:git 状态、已有指令文件、现存文档、技术栈与检查命令、LICENSE 等。能从仓库读到的事实不向用户提问。
- 决策分批提出,每批至多四项,每项附带默认值与一句理由;默认值只决定用户不回答时取什么,不决定问不问。
- 方案表列出每个将被创建、修改或移动的文件与命令,获得明确确认后才动手。
- 验证逐条执行检查命令,失败项如实报告,不以通过的名义带过。

## 决策清单

| 编号 | 决定 | 何时提出 |
|---|---|---|
| D1 | 可见性:尚未确定 / 开源 / 永久私有 | 每次运行,第一项 |
| D2 | 指令文件形态:AGENTS.md 为主 / 保留现有主文件 / 不动 | 已存在指令文件时 |
| D3 | 文档语言:全部跟随对话语言 / 公开文件英文、过程文档跟随对话 | 可见性非私有且对话非英文时 |
| D4 | 许可证与版权人 | 开源且尚无 LICENSE 时 |
| D5 | 完成门槛:判定一次改动完成所需通过的那条命令 | 探测到候选命令时 |
| D6 | 进度看板:kanban-hub / 不用 / TASKS.md | 每次运行,最后一批 |
| D7 | 远程仓库地址 | 仓库没有 origin 时 |
| D8 | 本机备注:当前阶段、硬性约束、参考项目的本机路径 | 隔离形态且 LOCAL.md 尚不存在时 |
| D9 | 过程文档目录:docs/ 被文档站占用时改用 project-docs/ | 追踪形态且 docs/ 是文档站源码时 |
| D10 | 项目名与一句话描述 | 两者都不存在于 README、manifest 或对话中时 |

决策表之外的事项(脚手架、技术选型、代码结构)不进入提问批次,写进收尾报告的建议。

## 文档模型

可见性(D1)决定形态,两种形态仅相差一层目录:

| 可见性 | 过程文档位置 | Git |
|---|---|---|
| 尚未确定或开源 | `docs/_internal/<分类>/` | 忽略 |
| 永久私有 | `docs/<分类>/` | 入库 |

默认取「尚未确定」:此时隔离只需一条忽略规则;若先入库再撤下,则需要改写 git 历史。

过程文档分七类:`research`(调研)、`discussion`(讨论)、`specs`(规格)、`plans`(计划)、`audit`(验收)、`reference`(资料)、`ui`(界面)。初始化只建立索引,分类目录在第一个文件写入时才创建。

治理记录位于索引顶部,记载可见性、形态、指令文件、文档语言、进度看板与接入日期。下一次会话与 `vibesop-init-deployment` 都从这里读取上下文。

## 指令文件

`AGENTS.md` 是主文件,内容为工作契约:一类改动放哪、需要什么测试、怎样算完成。其中每句话都来自探测到的事实、用户的决定或用户亲口所述,不虚构约定。`CLAUDE.md` 仅一行 `@AGENTS.md`,使各工具读到同一份规则。

本机信息(当前阶段、硬性约束、参考项目的本机路径)写入 `docs/_internal/LOCAL.md`,不进 git;配合 `CLAUDE.local.md` 的导入行,Claude Code 在会话开始时自动加载。存量项目的原有指令文件在转换时逐行保留,与仓库矛盾的行写进报告。

## 检查命令

同一组命令既验证新初始化,也用于日后的定期检查:

- 忽略规则来自仓库自身的 `.gitignore`,本机私有文件确实被忽略
- 没有被追踪的文件命中忽略规则
- 隔离形态下 `docs/_internal`、`CLAUDE.local.md` 不在 git 索引中
- 公开文件不指向内部文档
- 写入的文件没有残留模板占位符
- `AGENTS.md` 中写明的命令在仓库中真实存在

## 边界

git 的提交、推送与一切历史改写由用户执行,skill 只准备好命令。可见性、许可证、版权人、远程地址这类决定必须来自用户。

## 语言

对话使用用户所用语言;写入仓库的文件使用所选文档语言,内置中文与英文两套模板。
